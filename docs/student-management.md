# ТЗ №3: кабинеты и управление учениками

Изменения рассчитаны на ветку `feature/student-management`. Развёртывание и изменение production Firebase в эту работу не входят.

## Интерфейс и данные

- `/teacher`: сводка по классу, приглашения и существующие инструменты преподавателя.
- `/teacher/students`: поиск, фильтры, сортировка, профиль, проверка работ и управление доступом.
- `/student`: существующие задания, тесты и тренажёры, разделы материалов, профиля и оценок.
- `/invite/[token]`: регистрация по одноразовой ссылке. На главной странице сохранён вход и восстановление пароля.
- Компоненты: `src/app/student-access.tsx`, `src/app/student-record.tsx`. Кабинеты используют общий интерфейс из `src/app/page.tsx`.
- Новые назначения используют поля `assignments.audience` и `assignments.assignedToId`. Общие задания имеют явно заданное значение `class`; персональные используют UID. Работы сохраняются в существующей коллекции `submissions`. Оценка и комментарий меняются в исходном документе работы.
- Старые результаты остаются в существующих коллекциях. Доступ к ним по-прежнему учитывает email, чтобы сохранить историю; профили и новые назначения проверяются по UID.
- Связь с преподавателем создаётся сервером при принятии приглашения. Firebase Auth хранит пароль; Firestore хранит хеш токена, срок и статус приглашения.

## Переход со старых данных

1. В тестовом Firebase проекте или на копии данных снять резервную копию и проверить список существующих аккаунтов и связей.
2. С серверной переменной `FIREBASE_SERVICE_ACCOUNT_JSON` запустить `node scripts/migrate-assignment-audience.mjs`. По умолчанию скрипт только показывает идентификаторы и типы действий.
3. Для строк `requires manual review` определить владельца вручную: запись без однозначного соответствия остаётся недоступной ученикам. Не размечать спорные задания как общие. Старым аккаунтам без профиля `users/{uid}` и связи `teacherStudents` нужно подтвердить принадлежность, затем создать записи с их существующими UID через доверенное администрирование. Не создавать им новые аккаунты и не переносить историю на другой email.
4. После проверки отчёта `--apply` добавляет поля однозначным заданиям. Скрипт ничего не удаляет и отказывается перезаписывать запись, которая поменялась после чтения.
5. Только после проверки миграции и отдельного согласования синхронно выпустить приложение и правила. Иначе старый клиент запрашивает все задания разом, а новый скрывает немигрированные задания и не пропускает аккаунты без активного профиля.

## Почта

Ручная ссылка доступна сразу. Для автоматической отправки подключить HTTPS обработчик и задать серверные `INVITATION_MAIL_WEBHOOK`, `INVITATION_MAIL_TOKEN`, `INVITATION_PUBLIC_ORIGIN`. Приложение отправляет POST с Bearer токеном и JSON `{ email, displayName, invitationUrl }`. Обработчик должен подтвердить приём через 2xx и отправить письмо. Не писать ссылки с токенами в журнал. Статус «запрос принят» не является подтверждением доставки в почтовый ящик.

## Проверка

- Локально: `npm test`, `npm run test:assignment-access`, `npx next build --webpack`.
- Проверка правил на Firebase Emulator Suite: `firebase emulators:exec --project demo-physics-tutor --only auth,firestore "npm run test:classroom-rules"`. Скрипт принимает только локальные адреса эмуляторов.
- Сквозная проверка в отдельном тестовом Firebase проекте: войти владельцем, создать приглашение, открыть ссылку во втором браузере, зарегистрироваться и убедиться, что ссылка второй раз не работает. Назначить общую работу и индивидуальную двум ученикам, проверить, что каждый видит только свои и общие задания. Отправить решение, выставить оценку с комментарием, проверить её у ученика. Приостановить доступ и убедиться, что защищённые запросы отвергаются даже со старым токеном; восстановить доступ и убедиться, что работы сохранились. Проверить ЕГЭ, мини-тест, материалы и старые результаты.
- Файлы существующей загрузки Cloudinary открываются по прямой ссылке. Правила Firestore защищают записи со ссылками, но не блокируют уже известные прямые ссылки. Если материалы должны быть закрыты на уровне файла, требуется настроить приватное хранилище и перенести туда старые файлы.
