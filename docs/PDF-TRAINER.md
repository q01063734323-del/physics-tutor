# Тренажёр ЕГЭ: анализ PDF и проверочный импорт

Дата проверки: 17 ноября 2026 года. После первоначального пилота пользователь разрешил массовую локальную подготовку и полную сверку сборника. Подготовлена 1481 закрытая запись; полностью сверены 164 задач, 1317 ожидают проверки. В Firebase ничего не записывалось, публикация не выполнялась.

## 1. Что обнаружено в документе

Источник: «ЕГЭ-2026. Физика. Отличный результат. Учебная книга участника ЕГЭ», под редакцией М. Ю. Демидовой. SHA-256: `0a7b3ff6ccc721c16c4bd7819d08620b8a0d81f0f2a4cfd286ab0c1cef86043a`.

- 488 страниц, около 95 MiB; PDF состоит из сканов, встроенного текстового слоя нет.
- Локальное распознавание выполнено для всех 488 страниц. Текст не отправлялся во внешние OCR-сервисы.
- На обложке заявлено «Более 1600 заданий». **Точное количество отдельных задач ещё не подтверждено**: повторная нумерация, составные упражнения и таблицы ответов требуют разметки. Число с обложки нельзя считать результатом подсчёта.
- Найдены 13 тематических глав, раздел методов научного познания, входная диагностика, итоговая работа и задачи высокого уровня.
- Главы: кинематика, динамика, статика, законы сохранения, механические колебания и волны, молекулярная физика, термодинамика, электростатика, постоянный ток, магнитное поле, индукция и электромагнитные колебания, оптика и электромагнитные волны, квантовая физика.
- Условия включают текст, формулы, рисунки, графики и таблицы. Поиск упоминаний рисунков/графиков/схем срабатывает на 269 страницах; это **не число задач с рисунками**.
- Ответы начинаются с PDF-страницы 425; тематические ключи — с 433. В конце есть развёрнутые решения. Не у каждой задачи есть подробное решение.
- 252 страницы имеют среднюю уверенность OCR ниже 85. Эта метрика не оценивает математическую правильность и не заменяет сверку со сканом.
- Пример существенной ошибки OCR: коэффициент `1/2 F` в условии распознан как `3F`. Это упражнение не включено в проверочный набор.

Весь документ инвентаризирован и распознан; **не все задачи и рисунки вручную проверены**. Для 164 задач сверены полные условия, единицы, графики, ответы и связи с источником. Глава «Кинематика» проверена целиком: 91 задача.

## 3. Существующая архитектура и совместимость

Приложение использует Next.js App Router, React, TypeScript, Firebase и существующий банк `src/lib/question-bank.ts`. В нём 50 задач. Исходные задачи и маршруты не заменены. Для нового интерфейса создан адаптер: он сохраняет ID и содержимое старых задач и оставляет номер ЕГЭ неподтверждённым, если его не было в исходных данных.

Существующие механизмы проверки числовых ответов переиспользованы. Добавлена поддержка записи вроде `3e-19`; сохранена десятичная запятая. Авторизация, кабинеты, домашние задания, Firebase, Cloudinary и виртуальный класс в рамках импорта не менялись. Регистрация service worker отключена только при разработке, чтобы старые кешированные скрипты не мешали предпросмотру. Production PWA сохраняет прежнее поведение. В рабочую базу не отправлялись записи задач или попыток.

Новый компонент пока подключён **только к локальному предпросмотру**. Основной тренажёр публичного сайта не заменён этим прототипом. Облачное сохранение новых попыток и подключение утверждённого полного банка — следующий этап.

## 4. Структура банка

Одна запись содержит:

- стабильный ID из хеша документа и ключа упражнения, отдельную версию содержимого;
- происхождение, экзамен, год сопоставления и подтверждённый номер либо `null`;
- раздел и несколько тем: задача хранится один раз независимо от количества тем;
- полное условие с LaTeX, рисунки с хешами и координатами вырезки;
- тип ответа: число, последовательность, множественный выбор либо ручная проверка;
- эталон и решение только при наличии в источнике;
- название источника, PDF-страницу, печатную страницу, номер упражнения, страницы ответа и решения;
- статус прав, проверку условия, рисунков, формул, ответа и замечания преподавателя.

`canPublishQuestion` допускает новую задачу ученикам только после подтверждения прав, проверки преподавателем и всех обязательных проверок полноты. Исторические записи обрабатываются отдельно: новый статус не выдаётся им автоматически.

Фильтры «По номерам» и «По темам» независимы. Есть поиск, счётчик, фильтр по прогрессу, последовательное решение, ответ после попытки и возврат к ошибкам. Номер без подтверждения не угадывается. KaTeX отображает формулы с отключёнными доверенными HTML-командами.

Попытка привязана к ID и версии задачи. Изменение условия не переносит старую отметку «решено» на новую редакцию. В предпросмотре прогресс хранится только в браузере и не синхронизируется с аккаунтом. Компонент предусматривает обработчик сохранения попытки для последующей интеграции.

- Сверены 164 задач; 1317 требуют полной проверки.

## 6. Механизм импорта и продолжение

OCR сохраняет отдельный результат каждой страницы и продолжает с уже выполненного места. Хеш исходного файла защищает от смешивания разных документов. Изображения получают имена по содержимому. Подготовка задач использует отдельный проверенный план: OCR не считается надёжным источником математического эталона. Повторный запуск обновляет версию той же записи.

Первоначальный сборщик пилота ограничен 5–10 записями. После разрешения пользователя реализован отдельный сборщик полного закрытого банка `prepare-bank.py`. Он сохраняет все исходные страницы, выделяет обычные упражнения и тренировочные таблицы, связывает продолжения условий, ответы и решения. Непроверенный OCR не становится эталоном.

Оставшиеся этапы:

1. Размечать упражнения по главам с отдельными контрольными точками, извлекая границы условий и связанные рисунки.
2. Сопоставлять ответы из таблиц и решения со стабильными ключами «глава / подраздел / номер», не одним номером по всему PDF.
3. Сохранять кандидатов в закрытые пакеты; неоднозначные дроби, индексы, графики и таблицы отправлять в очередь проверки.
4. Проверять полноту условия, наличие рисунков, единицы, LaTeX, ссылки на страницы и повторы. При отсутствии достоверного ответа отключать автопроверку.
5. Уточнить точное число отдельных упражнений и составных подзаданий после разметки всего документа.
6. Дать преподавателю список, сравнение со сканом, исправления и утверждение каждой записи/пакета.
7. После урегулирования прав и отдельного разрешения на публикацию подключить утверждённые записи к существующему тренажёру и хранилищу прогресса. Черновики и эталоны не отдавать публичным чтением Firestore. Для настоящего контроля ответов проверка должна выполняться сервером: локальный прототип не защищает эталоны от просмотра в инструментах браузера.

Это план следующего этапа; не отчёт о выполненном массовом импорте.

## 7. Как открыть локальный результат

Из корня проекта:

```sh
PDF_IMPORT_PREVIEW=1 WATCHPACK_POLLING=true npm run dev -- --webpack --hostname 127.0.0.1 --port 3217
```

Открыть `http://127.0.0.1:3217/teacher/import-preview` на этом компьютере. Локальный сервер оставлен запущенным на момент передачи результата. После его остановки команду нужно запустить снова. Ссылка не предназначена для доступа учеников через интернет.

Повторная подготовка пилота требует Poppler, Python с pypdf/Pillow и существующего частного плана:

```sh
python3 scripts/pdf/prepare-pilot.py '/путь/к/исходному.pdf' .local/pdf-imports/pilot-plan.json
```

План содержит материалы книги, поэтому не включён в репозиторий. На другой машине его нужно предоставить отдельно. OCR-инструмент принимает PDF, частную папку результата, начальную/конечную страницу и число обработчиков. `TESSERACT_MODULE` задаёт локальный путь к tesseract.js; движок не добавлен в клиентские зависимости сайта. Модели OCR скачиваются, распознавание выполняется локально.
