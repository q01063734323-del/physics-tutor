# ЕГЭ Command Center 1.0 — отчёт о реализации

Дата: 20 ноября 2026. Ветка: `feature/ege-command-center`.

## Состояние

Реализованы интерфейс ученика и преподавателя, сбор новых PDF-попыток, серверная аналитика, локальная очередь синхронизации, темы/номера, рекомендации, ошибки, ручная проверка, настройки и история пробников. Изменения подготовлены локально. В этой работе новая версия на Render не публиковалась; рабочая Firebase не изменялась.

Полностью закрытой приёмку пока считать нельзя: необходимы проверка на настоящем iPhone/Android и проверка облачного сценария с реальными связанными аккаунтами после публикации. Прогноз балла намеренно недоступен без валидированной методики.

## Аудит и переиспользование

Проект: Next.js 16.4.3 / React 19 / TypeScript, App Router, Firebase Auth и Admin, Firestore, Render, существующий service worker PWA. Использованы локальные Inter и Manrope, существующие механизмы IndexedDB и серверной проверки ответов.

Единый опубликованный PDF-банк содержит 1 460 задач и 1 687 изображений. У 1 059 задач подтверждён номер ЕГЭ, у 401 номер не установлен: они доступны по темам. Разметка относится к сборнику 2026 и не переименовывается автоматически под следующий год. PDF-импортёр, условия, ответы, изображения и идентификаторы задач не изменены и не продублированы.

Существующие блиц и короткий вариант из 12 вопросов сохранены как учебные тренировки. Они не объявляются полноценным экзаменом. Домашние задания и расписание открываются через существующий кабинет. Studio и авторизация не переписаны.

## Что реализовано

- Страница `/preparation`, пункт «Моя подготовка» в навигации и ссылка из PDF-тренажёра.
- Обзор: цель, последний подтверждённый тестовый результат полного пробника, проверенные попытки, уникальные решённые задачи, точность, дни учебной активности.
- Периоды 7/30/90 дней и вся история; график точности или количества ответов с выбором дня, текстовыми подсказками и табличной альтернативой. Пропуски не заполнены фиктивными точками.
- Карта тем с доступным объёмом банка, точностью, покрытием, первыми ответами, осторожной категорией освоения и сравнением сопоставимых периодов.
- Карта подтверждённых номеров PDF-банка: объём, точность, последняя практика, предупреждение о малой выборке, переход к задачам.
- История ошибок: исходный ответ, дата, доступный эталон после проверки, повторные ошибки, повторное решение и похожая подборка. Причину ошибки может указать преподаватель; алгоритм не выдумывает её по одному неверному ответу.
- Непроверенные ответы показаны отдельно. Только связанный преподаватель может подтвердить верный/неверный ответ. До этого они не входят в метрики. Ручная проверка сохраняет автора, время и версию метода; повторный конфликтующий результат отклоняется.
- Объяснимые рекомендации: ошибки, небольшая выборка, отсутствие практики более 14 дней, приоритет преподавателя, совпадающая тема домашнего задания, близость заданной даты экзамена. Каждое предложение содержит причину.
- Персональная тренировка до пяти разных задач открывается в существующем тренажёре. Приоритет получают последние неверные ответы, затем новые задачи, затем уже опробованные. Ссылки поддерживают `topic`, `number`, `task`, `limit`.
- Настройки цели 0–100, года и реальной календарной даты с проверкой соответствия году. Дата помечена как пользовательская, а не официальное расписание. Дни и активность рассчитываются по Москве.
- Преподаватель видит список собственных активных учеников с последней активностью, открывает персональную аналитику, задаёт приоритетные темы и рекомендацию, классифицирует ошибки, проверяет ответы и вносит фактически проведённые полные пробники.
- Полные пробники: вариант/год/дата, первичный балл и максимум, необязательный подтверждённый тестовый балл, источник оценивания, «ожидает проверки» / «проверен». Ожидающий проверки пробник нельзя сохранить с тестовым баллом. Автоматического перевода по придуманной шкале нет.
- Понятные состояния загрузки, пустой истории, отказа доступа, недоступного облака, отсутствующей задачи и ожидания проверки.

## Формулы и ограничения интерпретации

Валидная попытка относится к существующей задаче и актуальной версии, имеет корректную дату не в будущем, статус `evaluated` и булев результат. Дубликаты ID учитываются один раз. Pending/cancelled/error не входят в точность.

- Точность = верные валидные попытки / все валидные проверенные попытки × 100%.
- Уникальные опробованные = количество разных taskId с валидными проверенными попытками в периоде.
- Уникальные решённые = количество разных taskId хотя бы с одним верным ответом в периоде.
- Покрытие = уникальные опробованные / доступные задачи выбранной темы или номера × 100%.
- Первые ответы = самый ранний зарегистрированный валидный ответ каждой опробованной в периоде задачи, включая более раннюю историю за пределами периода. Поздний повтор не заменяет первый ответ.
- Категория освоения доступна от 10 разных задач: точность первых ответов ≥80% — устойчивая, ≥50% — развивается, ниже — нужна практика. Это прозрачная эвристика по выборке, не доказательство освоения всей темы и не балл ЕГЭ.
- Активные дни = разные московские даты проверенных ответов; простой вход не учитывается.
- Динамика = разница точности в процентных пунктах между одинаковыми периодами, минимум по пять проверенных попыток с каждой стороны. Маленькая выборка явно обозначена.

Пустая точность — `null` / «Нет данных», а не 0%. Повторные попытки сохраняются, но не увеличивают число уникальных задач.

## Прогноз

Автоматический прогноз тестового балла не реализован намеренно: нет валидированной модели и подтверждённой применимости шкал. Точность PDF-задач не переводится в баллы 0–100.

Показываются только внесённые преподавателем результаты проверенных полных пробников выбранного года с указанным источником оценивания. При двух и более результатах отображается наблюдавшийся минимум–максимум. Это диапазон фактических результатов, не прогноз и не доверительный интервал. Непроверенные и короткие учебные варианты исключены.

## Данные и безопасность

Новые приватные коллекции создаются при первом использовании API:

| Коллекция | Назначение |
| --- | --- |
| `preparationAttempts` | Исходный ответ, UID, taskId/версия, результат серверной или ручной проверки, серверная дата, fingerprint |
| `preparationProfiles` | Цель, год, дата и её авторство, приоритетные темы, рекомендация |
| `preparationSummaries` | Только последняя активность для недорогого списка учеников |
| `preparationExams` | Подтверждённые преподавателем записи полных пробников |

Существующие `teacherStudents`, `users`, `assignments`, `examAttempts` читаются без миграции. Новых платных сервисов и зависимостей нет. Правила Firestore не ослаблялись: новые коллекции закрыты для прямого клиентского доступа и обслуживаются Admin API с обязательной проверкой прав.

API `/api/preparation` проверяет Firebase ID token с проверкой отзыва. Ученик получает только собственные данные. Преподаватель определён по существующему адресу проекта; для другого UID обязательны активная связь `teacherStudents` (либо прежняя связь без статуса) и активный профиль ученика. Архивные/посторонние/заблокированные ученики недоступны.

Сервер заново проверяет исходный ответ по существующему банку. Клиентские `correct`, баллы и дата не принимаются как достоверный результат. Для PDF-попыток экзаменационные баллы и время начала оставлены `null`, поскольку источник этих данных не предоставляет. Повторный UUID с тем же содержимым идемпотентен; иной ответ под тем же UUID получает конфликт 409.

Перед подтверждением сохранения результат помещается в IndexedDB-очередь текущего аккаунта. При сетевой ошибке очередь сохраняется; повторная отправка выполняется при входе/открытии тренажёра и событии восстановления сети. Удаляются только подтверждённые ID, параллельно добавленные записи сохраняются. Смена UID останавливает отправку очереди предыдущего пользователя. Демо и гость в облако не отправляются.

Приватные ответы API имеют `Cache-Control: private, no-store`. Существующий service worker исключает `/api/`, внешние запросы и приватный HTML из кэша. Авторизация и выход не заменяются новым механизмом. Демо использует отдельную локальную историю и не открывает реальных учеников; преподавательские изменения в демо заблокированы.

## Оставшиеся ограничения

1. Живой E2E «реальный ученик → Firebase → связанный преподаватель» ещё не выполнен в этой версии: локально нет настроенных Admin-данных. API проверен с подменённым внешним I/O. После публикации нужен этот сценарий на настроенном Render.
2. Новая облачная аналитика собирает новые PDF-попытки. Старый локальный прогресс сохранён, но автоматически массово не загружается. Перенос потребует явного механизма миграции с повторной серверной проверкой; старое клиентское время нельзя выдавать за серверное.
3. Мини-экзамены и блиц показаны отдельно. Они не смешаны с PDF-точностью и не конвертируются в тестовый балл.
4. Полные пробники пока вносятся преподавателем по реально проведённому варианту. Генератор полноценного онлайн-экзамена и автоматическая проверка развёрнутых решений не добавлялись.
5. Чтение одной истории ограничено 5 000 попыток: при превышении возвращается явная ошибка, а не усечённая аналитика. Для больших историй нужна постраничная/инкрементальная обработка. Список связей — до 200, история коротких тренировок — до 100, полных пробников и персональных ДЗ — до 200. Эти списки пока не имеют пагинации.
6. В центре отображаются персонально назначенные ДЗ. Общие задания и расписание доступны в существующем кабинете; общий статус не подменяется индивидуальным результатом сдачи.
7. Нет доказанной прогностической модели, нагрузочного испытания на тысячах реальных попыток и замера производительности на физическом телефоне. Эвристика освоения не учитывает все психометрические факторы и явно так обозначена.
8. Демо-преподаватель показывает локальную учебную историю и блокировку облачных изменений; полный цикл ручной проверки проверен API-тестом.

## Деплой и приёмка

Новая версия пока локальная. Перед публичной публикацией требуется подтверждение владельца.

1. Опубликовать проверенную ветку в GitHub и перенести в ветку, которую отслеживает Render (`feature/student-management` по текущей настройке), либо выбрать новую ветку в Render.
2. Сохранить текущие настройки Firebase и `FIREBASE_SERVICE_ACCOUNT_JSON` в серверном окружении Render. Секрет не помещать в GitHub и `NEXT_PUBLIC_*`. Новых переменных для Command Center нет.
3. Сборка `npm ci && npm run build -- --webpack`, запуск `npm run start`, существующий HTTPS и health check. Новый сервис не нужен.
4. Не публиковать новые разрешающие правила Firestore: запросы проходят через защищённый серверный API. Текущие запросы используют стандартные индексы по UID/связи; если рабочий проект потребует составной индекс для `teacherStudents`, создать только указанный Firestore индекс, не менять права.
5. После деплоя открыть `/preparation`, войти активным учеником, решить задачу, дождаться сообщения синхронизации, проверить свою статистику, открыть этого ученика преподавателем и повторить после перезагрузки/смены устройства. Проверить отказ чужому UID и отсутствие приватного кэширования после выхода.
6. На iPhone и Android проверить вкладки, ввод цели, safe-area, график, очередь при потере сети, возврат в тренажёр, установленную PWA и поворот экрана. Только после этого считать мобильную приёмку завершённой.

Демо-пути после запуска локально или публикации:

- `/preparation?demo=student` — локальная история демо-ученика.
- `/trainer?demo=student` — создать настоящие локальные учебные попытки для демонстрации.
- `/preparation?demo=teacher` — безопасный демо-список без настоящих учеников.
- `/preparation?demo=teacher&student=demo-student` — открыть локальную демо-аналитику и проверить запрет облачных изменений.

При пустом хранилище числа не подставляются: сначала нужно решить задачу в демо-тренажёре.
