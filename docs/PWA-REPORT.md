# PWA «Физика с Егором»

Дата проверки: 16 ноября 2026 года. Сайт: https://physics-tutor-6ytz.onrender.com

Render: финальный коммит e9b7eb92d3ce579c73cd0d9cb47130480b341024, статус Live. Ветка feature/student-management.

## Реализовано

Существующий Next.js App Router сохранён. Новые платные сервисы и зависимости не добавлены.

- Manifest: имя «Физика с Егором», короткое имя «Физика», standalone, start_url и scope `/`, стабильный id `/`, цвета `#07142B`.
- Использована предоставленная фотографическая иконка: 192×192, 512×512, Apple Touch 180×180; maskable 512×512 с изображением 400×400 по центру и полями 56 px. Лицо не обрезано, новая генерация не применялась.
- Favicon ICO с корректными RGBA PNG 32×32 и 48×48.
- iOS: Apple Touch Icon, название, standalone-метаданные, viewport-fit=cover; безопасные зоны экрана. Мобильные поля ввода 16 px и основные элементы управления не менее 44 px.
- Service worker регистрируется на всех маршрутах. Новая версия предлагается кнопкой «Обновить»; автоматической перезагрузки урока нет.
- Отдельная автономная offline.html без внешних шрифтов и скриптов.
- Кешируются только offline-страница, иконки и подходящие статические JS/CSS/шрифты Next.js. HTML кабинетов, RSC, API и сторонние сервисы не кешируются. Firebase Authentication, Firestore и Cloudinary обходят обработчик. Старые кеши только с префиксом physics-tutor- удаляются при активации.
- Навигация получает HTML из сети, при сетевой ошибке показывает offline.html. Поэтому кеш не подменяет актуальные задания и результаты.
- Заголовки запрещают устаревший кеш sw.js и требуют проверки manifest.

## Выполненные проверки

- Production build: `npm run build -- --webpack` — успешно, 18 статических страниц; маршруты API и кабинетов сохранены.
- `npm run lint` — успешно.
- `npx tsc --noEmit` — успешно.
- `npm test` — успешно: проверка ответов, dashboard, загрузки файлов, банк задач, формулы, кинематика, валидация класса, конфигурация доступа и приглашения.
- Поведенческая проверка service worker в Node VM: обход Auth/Firestore/API/POST/RSC, отсутствие HTML в кеше, offline fallback, повторное чтение статического файла из кеша, удаление только собственных старых кешей, активация обновления только по сообщению.
- Все семь публичных URL manifest, sw.js, offline.html и четырёх иконок вернули HTTP 200; содержимое совпало с локальными файлами; MIME-типы и заголовки кеширования корректны.
- Публичная offline-страница отображается, иконка загрузилась 192×192. Публичный кабинет демо-ученика открывается. Снимки: pwa-verification/dashboard.jpg и pwa-verification/offline.jpg.
- В публичном кабинете появился диалог обновления от зарегистрированного service worker. После нажатия «Обновить» произошла перезагрузка; демо-кабинет восстановился, предложение обновления исчезло. Это подтвердило регистрацию и активацию обновления через пользовательский интерфейс.
- На финальном публичном HTML подтверждены apple-mobile-web-app-capable=yes, theme-color=#07142B, Apple Touch Icon и viewport-fit=cover.
- Размеры PNG проверены через sharp. Масштабирование сохраняет пропорции.

## Ограничения проверки

Реальная установка на iPhone и Android, запуск с главного экрана, клавиатура и поворот экрана не проверялись. Изменение viewport во встроенном браузере не сработало: документ оставался 1024 px. Поэтому мобильную проверку на устройствах нельзя считать выполненной.

Регистрация и обновление service worker подтверждены через интерфейс приложения. Полноценный offline-переход с отключением сети в браузере не удалось проверить доступными средствами; поведение fallback проверено отдельно в Node VM. Lighthouse-аудит не выполнялся.

Повторный вход реальным аккаунтом Firebase и обмен реальными домашними работами в рамках этой PWA-проверки не выполнялись; интеграционные сценарии требуют отдельного прохода. Их запросы не затрагиваются новым кешем.

Локальный Turbopack упирался в запрет среды на привязку служебного порта. Production-сборка Webpack прошла. Render самостоятельно успешно собирает опубликованный проект.

## Установка

**iPhone:** открыть сайт в Safari → «Поделиться» → «На экран Домой» → включить «Открывать как веб-приложение», если такой переключатель показан → «Добавить». Затем открыть новую иконку. [Инструкция Apple](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios).

**Android:** открыть сайт в Chrome → меню ⋮ → «Добавить на главный экран» → «Установить»; либо использовать кнопку «Установить», если её предлагает сайт. [Инструкция Google](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=ru).

## Render и обновления

Текущая инфраструктура Render и HTTPS подходят для PWA. Отдельные сервисы и платные настройки не нужны. Деплой идёт из ветки feature/student-management. При изменении offline-страницы или иконок увеличивать версию CACHE_NAME в public/sw.js. Не добавлять кеширование `/`, кабинетов, API, Firebase или учебных данных.

Бесплатный Render может засыпать при неактивности: установка PWA не устраняет задержку запуска сервера. Это не требует оплаты для работоспособности, но влияет на время первого открытия.
