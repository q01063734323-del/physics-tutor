# Physics Library и Physics Studio 2.0 — результат реализации

Ветка: `feature/physics-library-studio-2`. Сначала реализована библиотека (коммит `ecc9540`), затем улучшения студии и дополнительные проверки. Изменения подготовлены локально. Новая версия на Render и правила Firebase в рамках этих ТЗ не публиковались.

## Что доступно в интерфейсе

### Библиотека и презентация

- Страница `/library`: личные материалы преподавателя, тематические и собственные папки, поиск, сортировка, число страниц и размер файла, переименование, перемещение и удаление.
- Загрузка PDF с фактическим прогрессом передачи, отменой и последующей серверной проверкой; повторная загрузка тех же байтов не создаёт дубликат.
- Приватный предпросмотр через PDF.js, многостраничность, увеличение до 300%, Retina с ограничением размера canvas. Соседние страницы подготавливаются без преобразования всего файла в JPEG. Отменённый рендер завершается перед повторным использованием canvas.
- Из библиотеки можно открыть класс; внутри урока преподаватель выбирает PDF и запускает показ. Перелистывание синхронизируется; увеличение у ученика локальное. Показ PDF не пересоздаёт комнату видеосвязи.
- Единый Canvas-инструментарий для доски и слайда: ручка, маркер, ластик, стрелка, линия, прямоугольник, цвет/толщина, отмена/повтор и очистка с подтверждением. Координаты привязаны к странице, а не размеру экрана.
- Пометки хранятся по уроку, документу, странице и ученику. Можно восстановить материал из прошлого урока того же ученика. Восстановление копирует страницы, не меняет исходную историю и атомарно заменяет текущие пометки; сбой записи сохраняет прежнее состояние.
- Оригинал и версия с пометками выдаются отдельно. PDF с пометками действительно формируется на сервере из векторных штрихов; оригинальный файл не изменяется. Есть скачивание, выдача связному активному ученику и отзыв доступа.
- У ученика в библиотеке видны только выданные материалы. Просмотр в текущем уроке не равен постоянной выдаче файла.
- PowerPoint: экспортировать презентацию в PDF, затем загрузить в библиотеку. Импорт PPT/PPTX и серверная конвертация не добавлялись. Анимации PowerPoint показывать демонстрацией экрана; они не сохраняются в статическом PDF.

### Студия

- Камера и демонстрация остаются независимыми LiveKit-треками. Новый ручной PeerConnection, SDP-модификации и альтернативный сервер звонков не добавлялись.
- Профили демонстрации: Auto — ориентир 1080p/15 FPS/4 Мбит/с; Presentation — 1440p/15 FPS/6 Мбит/с; Motion — 1080p/30 FPS/6 Мбит/с. При save-data запрашиваются 720p и 2 Мбит/с; для статических материалов — 10 FPS. Эти значения являются запросами, не фактическими результатами.
- Камера запрашивает 720p/30 FPS с отдельным кодированием до 1,8 Мбит/с и безопасным fallback. Камера не наследует приоритет статического текста.
- Панель качества показывает доступные реальные размеры захвата, кодирования и получения, FPS, битрейт, RTT, потерю пакетов, кодек, ICE-типы и ограничение качества. Недоступные значения не выдумываются.
- Общая доска рисует локально через requestAnimationFrame. Промежуточные точки передаются в LiveKit отдельно от записи законченного штриха; снимок canvas не отправляется на каждое движение. Поддержаны отмена указателя, фильтрация устаревших пакетов, запрос состояния при переподключении, немедленные erase/clear notifications.
- Незавершённые облачные операции доски и пометки PDF сохраняются в IndexedDB с разделением по аккаунту/комнате. После восстановления сети отправка возобновляется, неуспешные команды не подтверждаются как сохранённые. Переполненная очередь/недоступное локальное хранилище сообщают об ошибке.
- Studio, Cinema, Whiteboard и существующее свободное расположение; переключение доски/PDF/видео, камеры, чат, устройства, полный экран, zoom демонстрации. Сохранены существующие модерация ученика и завершение урока.

## Приватность и хранение

Cloudinary-загрузка домашних работ в проекте публичная, поэтому для приватных PDF она не использована. Возможность Firebase Storage без смены тарифа не подтверждена; платная инфраструктура не включалась. Применён ограниченный адаптер поверх существующего Firestore:

| Данные | Где хранятся |
|---|---|
| Метаданные / исходные PDF | `libraryDocuments`, бинарные части в подколлекции `chunks` |
| Квоты / SHA-256-дедупликация | `libraryAccounts`, `libraryHashes` |
| Папки / выдачи | `libraryFolders`, `libraryGrants` |
| Текущий документ / пометки страниц | `librarySessions`, подколлекция `pages` |
| Неотправленные действия | IndexedDB конкретного браузера, ключи аккаунта и комнаты |

Доступ только через серверный `/api/library`: Firebase ID token или проверенный токен текущего гостевого урока; роли и состав комнаты перепроверяются сервером. Новые коллекции не открываются клиентскими правилами. ID файла сам по себе не даёт доступ. Ответы `private, no-store`; действующий service worker не кеширует `/api/` и приватные PDF. Секреты не передаются в браузер.

Лимиты: до 8 МиБ и 300 страниц на PDF, 64 МиБ/100 файлов преподавателя; гостевой набор — суммарно 8 МиБ/3 файла. На странице до 160 штрихов, в уроке до 300 сохранённых страниц пометок и 4 МиБ пометок. Некорректные/защищённые/активные PDF отклоняются. Это проверка известных опасных структур, а не антивирус и не обещание поддержки всех разновидностей PDF.

Гостевой доступ прекращается по сроку существующего гостевого урока (обычно 4 часа). Физическое удаление временных файлов выполняется при завершении урока; для брошенных уроков предусмотрена ограниченная очистка при следующей загрузке. Без последующих загрузок точное время физического удаления не гарантируется. Учительские файлы хранятся до удаления преподавателем. При сбое удаления доступ уже закрыт, квота удерживается, интерфейс предлагает повторить очистку.

Новые платные сервисы, подписки и серверы не добавлены. PDF.js/pdf-lib бесплатны. Операции и бинарные части расходуют существующие квоты Firestore; бесплатность любого объёма использования не гарантируется. Для большой библиотеки предпочтителен будущий авторизованный object storage после проверки тарифа. Текущий адаптер намеренно ограничен.

## Проверки и доказательства

- `npm test`: общий набор ЕГЭ, домашней работы, банка задач, формул, кинематики, виртуального класса, безопасности, приглашений, Blitz и Command Center; новые тесты библиотеки, качества и очереди доски.
- `npx tsc --noEmit`, `npm run lint`, `npm run build -- --webpack`.
- Тест библиотеки выполняет настоящий обработчик API и pdf-lib: загрузка/квота/дедупликация, отказ посторонним, выдача/отзыв, роли и истечение гостевого урока, очистка бинарных частей, страничные пометки, запрещённое смешение учеников, успешное восстановление и сохранность при ошибке, экспорт и неизменность оригинала. Firebase I/O подставлен.
- Тесты медиа: профили и Safari-fallback, раздельные настройки камеры/экрана, отсутствие повторного запроса после отмены, сохранение simulcast scales, недоступные поля статистики, вычисление битрейта/FPS, сброс счётчиков. LiveKit/браузерные устройства подставлены.
- Тест очереди: сохранение при offline/сбое, конкурентно добавленная команда не теряется при подтверждении, изоляция комнат/аккаунтов, ошибка IndexedDB. Хранилище/транспорт подставлены.
- Синтетический PDF из четырёх страниц с crop box и поворотами 0/90/180/270 реально экспортирован с пометками, отрендерен Poppler и просмотрен. Положение штриха сохраняется в координатах отображаемой страницы. Это проверка PDF-артефакта, а не скриншот интерфейса.

## Что ещё не подтверждено

- Реальный Mac Safari → iPhone PWA и другие пары устройств, звук/камера/экран в этой версии.
- Точные реальные разрешения, FPS, битрейт, RTT, локальная/удалённая задержка и память длительного урока: панель для измерений добавлена, результаты физического сеанса пока отсутствуют.
- Исчезновение синего артефакта: исходный сценарий не воспроизведён, точная причина неизвестна. Локальная защита от выделения/подсветки реализована; диагноз не подменяется предположением.
- Мобильная визуальная проверка, поворот настоящего iPhone и полноценный end-to-end PDF между двумя браузерами. Безопасный локальный сервер запускался, но подключение встроенного браузера возвращало connection refused. Публикация ради обхода этой проверки не выполнялась.
- Настоящие записи/чтения нового API в рабочем Firebase и проверка деплоя Render. Локально отсутствуют необходимые приватные серверные параметры для полноценного интеграционного сеанса.
- Прямой PPTX и сохранение его анимаций не входят в реализованный PDF-путь. Автоматическая конвертация не подключена.

Поэтому автоматические проверки и сборка подтверждены, а полную приёмку второго ТЗ на реальных устройствах пока нельзя объявить завершённой.

## Проверка пользователем после публикации

1. На Mac войти преподавателем, открыть «Библиотека», загрузить PDF до 8 МиБ с формулами и графиком. Проверить папку, поиск, предпросмотр и повторную загрузку без дубликата.
2. Открыть обычный урок с учеником; на iPhone войти учеником в ту же комнату. Включить камеры/микрофоны, проверить разговор в обе стороны.
3. В студии открыть библиотеку и начать PDF. Перелистнуть несколько страниц. Нарисовать стрелку на формуле; проверить появление во время движения, точность привязки после zoom/поворота iPhone, undo/redo/clear.
4. Переключить Studio/Cinema/Whiteboard, затем PDF обратно; звук должен продолжаться. Ученик обновляет страницу и получает актуальный слайд/пометки.
5. Выдать оригинал и отдельный PDF с пометками. В аккаунте ученика скачать оба, сравнить; отозвать доступ и проверить повторную загрузку (уже скачанную копию отозвать невозможно).
6. Открыть следующий урок с тем же учеником, восстановить прошлую презентацию. Для другого ученика история должна быть недоступна.
7. Запустить screen share со статическими формулами, открыть панель качества. Записать реальные capture/outbound/inbound размеры, FPS, битрейт, потери/RTT. Сравнить Auto/Presentation/Motion. Отмена выбора и остановка источника не должны завершать звонок.
8. Кратко выключить сеть, восстановить её, проверить актуальный слайд/итоговые штрихи и уведомления сохранения; затем провести длительный урок и следить за памятью/сбоем звука.
9. Для гостевой комнаты проверить два разных приглашения, временный PDF и завершение комнаты. Посторонняя ссылка или просроченное приглашение не должны открывать материалы.

## Render

При публикации использовать существующий сервис, Firebase Admin и LiveKit-параметры; новые ключи для PDF не требуются. `npm ci` запускает postinstall; `npm run build -- --webpack` запускает prebuild. Скрипт готовит совпадающие с установленной версией PDF.js worker, cmap/fonts/wasm в `public/pdf-assets`. Эти сгенерированные файлы не нужно вручную добавлять в Git. Правила Firestore для библиотеки открывать не требуется.

Если Firebase Admin уже отсутствует или некорректен на сервере, API библиотеки сообщит ошибку; это нужно исправить в существующей серверной конфигурации, не добавляя секреты в клиент или репозиторий.
